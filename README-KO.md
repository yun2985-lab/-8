# Watch Lite 0.1.0 — 독립형 Wear OS 개발 프로토타입

JJ, 휴대폰 동반 앱, 서버 연동을 제외한 첫 소스 버전입니다. **APK 빌드와 실제 워치 실행은 아직 검증하지 않았습니다.** Wear OS 기반 갤럭시 워치를 대상으로 하며, 구형 Tizen 워치는 지원하지 않습니다.

## 구현 범위

| 항목 | 현재 동작 |
|---|---|
| Normal / Lite | 앱 창 밝기 기본값 / 15%, GPS 요청 최소 간격 10초 / 60초 |
| 여기 기억해 | 최대 60초 동안 정확한 위치를 기다린 후 내부 DB에 저장 |
| 경로 기록 | 사용자가 시작한 위치 포그라운드 서비스, 화면이 꺼져도 기록 요청 유지 |
| BackTrack | 저장 경로의 지점을 역순으로 안내, 북쪽 기준 방위와 직선 거리 표시 |
| 저장 장소 | 좌표·저장 시각 목록, 선택 위치까지 직선 안내 |
| 배터리 | 워치 전체 배터리 변화로 시간당 소모율 및 5% 여유를 뺀 잔여 시간 추정 |
| 목표 시간 | 24 / 48 / 72시간을 추세와 비교해 설정 변경 권고 |
| 타이머 | 워치 기본 타이머 화면을 여는 인텐트, 미지원 기기는 안내 |
| 데이터 삭제 | 위치 기록 전체 삭제, 백업 비활성화 |

**Lite는 시스템 초절전 모드가 아닙니다.** 다른 앱, 건강 센서, LTE, Wi-Fi, AOD를 강제 종료하지 않습니다. 전화·문자·알림은 기존 시스템 설정대로 동작합니다. GPS 요청 간격을 늘린다고 GPS 하드웨어가 같은 비율로 꺼지는 것은 아닙니다. 배터리 개선율·48시간 지속을 보장하지 않습니다.

Ultra / Emergency, 자동 모드 전환, 알림 방화벽, 위치 리마인더, 생활기록, 일행 찾기, 음성 명령은 이번 버전에 포함하지 않았습니다.

## 빌드

Android Studio에서 이 폴더를 프로젝트로 엽니다. JDK 17, Android SDK 35, Gradle 8.11.1을 사용합니다. Gradle Wrapper 바이너리는 포함하지 않았습니다. IDE의 Gradle 배포판 설정 또는 설치된 Gradle을 사용하세요.

```sh
bash tests/run.sh
gradle :app:assembleDebug :app:lintDebug
```

APK 경로: `app/build/outputs/apk/debug/app-debug.apk`

GitHub 저장소 루트에 프로젝트를 넣으면 `.github/workflows/build.yml`에서 빌드 후 APK를 Actions 아티팩트로 받을 수 있습니다. 이 패키지를 GitHub에 업로드하거나 Actions를 실행한 상태는 아닙니다. CI debug 키는 실행 환경에 따라 달라지므로, 반복 업데이트용 서명은 별도로 안정화해야 합니다. 서명이 바뀌어 앱 삭제가 필요하면 로컬 위치 데이터도 삭제됩니다.

워치 설치는 개발자 옵션의 무선 디버깅에서 표시되는 페어링 주소와 연결 주소를 각각 사용합니다.

```sh
adb pair WATCH_IP:PAIR_PORT
adb connect WATCH_IP:DEBUG_PORT
adb -s WATCH_IP:DEBUG_PORT install -r app/build/outputs/apk/debug/app-debug.apk
```

휴대폰에서 APK를 눌러 설치하는 것은 워치 설치가 아닙니다.

## 최초 사용

1. 알림 권한과 정확한 위치 권한을 허용합니다.
2. 야외에서 '여기 기억해'를 누르고 저장 성공을 확인합니다.
3. '경로 기록 시작'으로 짧고 익숙한 구간을 걷습니다.
4. 'GPS / 기록 중지' 후 'BackTrack'을 선택합니다.
5. 안내를 마치면 GPS 작업을 중지합니다. 알림에서도 중지할 수 있습니다.

GPS 오차가 35m보다 크거나 좌표가 30초보다 오래되면 안내를 보류합니다. 도착 판정은 오차 20m 이하에서만 수행합니다. 한 좌표 갱신에서 한 지점만 통과시켜 교차 경로를 건너뛰지 않도록 했습니다. Lite에서는 위치 간격 사이에 '새 GPS 위치 대기'가 표시될 수 있습니다. 정밀한 되돌아가기는 Normal로 시험하세요.

방위는 **북쪽 기준**이며 손목이 향하는 방향을 감지하는 나침반 화살표가 아닙니다. GPS 경로는 실제 보행로를 보장하지 않고 실내·지하 주차장에서는 정확도가 부족할 수 있습니다. Lite의 성긴 기록은 급커브를 생략할 수 있습니다. 긴급 구조나 유일한 등산 길찾기 수단으로 설계하지 않았습니다.

서비스는 강제 종료·재부팅 후 자동 재시작하지 않습니다. DB의 경로는 유지되지만 GPS 작업을 다시 시작해야 합니다. BackTrack 진행 위치는 화면 인스턴스 내 상태이며 앱이 재생성되면 다시 시작해야 합니다. 기록 상한은 5,000개이며, 도달하면 기록을 종료합니다.

## 측정과 의사결정

배터리 수치는 앱만의 전력 사용량이 아닌 **워치 전체 소비량**입니다. 최소 1시간과 2% 감소 전에는 추정치를 표시하지 않습니다. 충전 관측, 모드 변경, 재부팅 감지 시 측정을 초기화합니다. 앱이 닫힌 사이의 충전은 일부 놓칠 수 있으므로 비교 시험 전 '배터리 측정 초기화'를 누릅니다. 잔여 시간은 현재 소비율이 지속된다는 가정이며 신뢰구간은 아직 없습니다.

- 핵심 가설 1: 자체 GPS·화면 조절이 워치 전체 사용시간을 유의하게 개선하는가 — 미검증.
- 핵심 가설 2: 성긴 GPS 기록으로도 경로를 되짚을 수 있는가 — 미검증.
- 핵심 가설 3: 휴대폰 없이 위치 저장·되돌아가기를 실제 사용하는가 — 미검증.

첫 실험은 동일한 밝기 외 조건·알림·운동 설정에서 Normal / Lite를 각각 6시간 이상, 순서를 바꿔 3쌍 비교하는 것입니다. GPS를 사용하지 않는 시험과 동일 경로 기록 시험을 분리합니다. 충전·업데이트·통화 시간 차이는 기록하고 통제가 안 된 회차는 재측정합니다.

제안 기준: 중앙값 소비율이 15% 이상 감소하고 안내 누락이 없다면 절전 방향 Continue. 15% 미만이지만 위치 기능이 유용하면 GPS 도구로 Pivot. 위치 효용도 낮으면 기능 확대 Stop. 15%는 제품 판단용 임시 기준으로, 검증된 효과가 아닙니다.

## 구조 / 나중에 JJ로 이식

- `Core.java`: 플랫폼 독립 거리·방위·정확도·배터리 계산.
- `Store.java`: 로컬 위치 저장소.
- `TrackService.java`: 사용자 시작 GPS 수명주기.
- `MainActivity.java`: 원형 화면용 세로 스크롤 UI.

연동 전용 권한이나 가짜 API를 미리 넣지 않았습니다. 추후 JJ 앱의 실제 프로토콜을 확인한 다음 Core / 저장 모델을 재사용할 수 있습니다.
